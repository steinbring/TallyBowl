# Frame recognition

All recognition runs on the device. Android uses bundled Latin ML Kit; iPad and Mac use Apple Vision. `PhotoService` first keeps the existing bounded OCR/aspect/regional pipeline (at most four native calls). A complete validated name match exits early.

Some QubicaAMF monitor photos produce readable totals but omit isolated strikes, circled split digits, and short misses. Treating those text rows as frame records left empty inputs. The shared `FrameGlyphReader` fallback now reads the photographed delivery ink directly when OCR remains incomplete. It requires a matching profile alias and at least six consistent numbered frame headers before decoding a bounded raster (longest side at most 4096). Classification runs in a worker isolate to keep the editor responsive. Flutter's codec applies EXIF orientation, including the upside-down EXIF orientation in the 109-pin regression photo.

Complete photographed component order takes priority when it can be read; complete native OCR preserves obscured marks when the component reading is incomplete. Numbered headers establish the column spacing and slope. Repeated photographed dark grid rulings calibrate the column centers, because some league monitors right-align their header numerals. A bounded family of seven line slopes follows tilted rulings. A ruling must remain dark over 85% of the sampled player band, and at least six boundaries must agree on the offset. The name anchor follows the header slope across angled photos; frame regions exclude the rulings and keep the complete delivery band. Row bounds stop at that bowler's cumulative band rather than covering neighboring bowlers.

Light, low-chroma ink is isolated from the saturated monitor background. Four-connected components separate characters; an enclosing split ring is removed only when it contains a separate ink component. Miss marks require a compact horizontal component in the middle of the delivery band. Short, rounded misses can have an aspect ratio as low as 1.2 only when at least 70% of their rectangle contains observed ink; ordinary thin misses retain the earlier shape checks. Digits, X, and / are compared with 24×32 binary templates rendered from OFL Roboto at six weights. Unknown shapes remain empty. Foul glyphs and unfamiliar fonts continue through native OCR/manual review.

Uncorroborated template acceptance requires intersection-over-union of at least .68 and a .06 lead over other characters. An independently observed native OCR character anchored inside a component is retained, including when color thresholding fragments the photographed ink. A secondary native observation can corroborate only the same pixel winner at the same position (IoU at least .6); it cannot override a different pixel winner or any conflicting primary character. A Cyrillic З/Х lookalike is accepted only with agreement from the pixel winner, never as a global name or score substitution. Conflicting primary native observations make that frame uncertain; templates fill omissions rather than overwrite known marks. No search chooses marks to fit a total. A full legal ten-pin sequence must match the independently observed final total, plus every cumulative checkpoint available from the native grid. Multiple matching rows still require selection. The photo and all ten filled inputs remain available for visual review before saving.

Full-image aspect readings are retained as alternatives to the refined reading. They share one bounded fallback raster decode; optional pixel-calibrated native crops use a separate sequential decode that is disposed before fallback. Observed layouts can be reused across passes from the same photo, while each pass keeps its own frame observations and validation. Identical recovered rows are deduplicated; conflicting complete readings disable automatic selection. Overlapping native words with identical text and at least 65% overlap of the smaller box are collapsed, avoiding ML Kit duplicate-block conflicts. Distinct values in the same cell remain conflicts.

League scratch and handicap-adjusted totals are separate columns. Only the nearby first total column can validate a scratch game; multiple numeric columns require an identified handicap header. The common OCR c/e confusion in `hdcp` is allowed in that label, never in score digits. If one aspect pass loses the large scratch total, another pass may supply that actual observation only at the same name/row position, with six agreeing cumulative checkpoints including the observed tenth-frame total. A neighboring bowler, a handicap total, or cumulative numbers without delivery ink cannot supply missing rolls. No handicap is added to the journal's scratch score.

`assets/recognition/glyphs.json` is a small bundled template set, not a downloadable service or remote model. Its source URL, source-font SHA-256, and OFL license are recorded alongside it. Regenerate using `tool/generate_score_glyphs.py` with the Google Fonts Roboto variable font and Pillow. The full source font is not bundled. Settings → Licenses includes the template license.

## Regression evidence and limits

The original photos, original name, venue/background, EXIF, and native diagnostic logs are not committed or distributed. The corresponding Apple/Android JSON records preserve native OCR geometry after the crop transform. Tests verify every delivery, mismatched totals, incorrect names, native-mark conflicts, and the actual import/resume → editor → saved-game flow. Private end-to-end checks also run the complete production pipeline against both original JPEGs on Mac and an isolated Android emulator.
