# Frame recognition

All recognition runs on the device. Android uses bundled Latin ML Kit; iPad and Mac use Apple Vision. `PhotoService` first keeps the existing bounded OCR/aspect/regional pipeline (at most four native calls). A complete validated name match exits early.

Name matching uses one shared normalizer. It retains visually identical Latin/Greek/Cyrillic capitals that OCR sometimes mixes inside a Latin name (for example the Cyrillic A in `KАT`). This applies only to names, never to score or delivery text. It does not replace digits with letters, perform fuzzy spelling matches, or resolve competing player rows. Both matching rows still require confirmation.

Some QubicaAMF monitor photos produce readable totals but omit isolated strikes, circled split digits, and short misses. Treating those text rows as frame records left empty inputs. The shared `FrameGlyphReader` fallback reads the photographed delivery ink directly when OCR remains incomplete. A matching profile alias is required. Six distinct numbered headers can establish a layout; three to five require at least six independently observed, consistently spaced grid rulings. Duplicate OCR header observations cannot raise that confidence. Raster decoding is bounded to a longest side of 4096, and classification runs in a worker isolate. Flutter's codec applies EXIF orientation, including the upside-down EXIF orientation in the 109-pin regression photo.

Complete photographed component order takes priority when it can be read; complete native OCR preserves obscured marks when the component reading is incomplete. Numbered headers establish column spacing and slope. Both bright and dark rulings can calibrate column centers. A bounded family of seven line slopes follows tilted rulings; a ruling must retain its polarity over 85% of the sampled player band, and six boundaries must agree on the offset. Up to two supported header fits and two independently confirmed ruling polarities are retained per name instead of choosing geometry from contrast alone. The name anchor follows the header slope across angled photos; frame regions exclude the rulings and stop before the cumulative band.

For sparse headers only, six measured rulings spanning at least five column intervals can correct a small linear spacing drift (0.5–5% of pitch, residual below 3.5% of pitch). Dense-header layouts preserve their established spacing. Regional retries inspect layouts in stable header-support order until one has supported physical rulings: a repeated footer name without rulings cannot hide the actual player row.

An otherwise incomplete delivery crop can retry its existing ink masks after removing a measured long boundary ruling. Removal follows connected ink only within narrow peripheral strips; disconnected glyphs and interior marks remain. Previously complete pixel or native frame readings are preserved. This adds no native OCR calls and does not change acceptance thresholds or score validation. Tests cover real photographed strike ink with an added bright border, short misses, narrow digits, interior strokes, and empty grid outlines.

For a small table, `ScoreboardFocus` can reuse the last full-context OCR retry to crop around an observed alias and nearby numbers while retaining headers and space for separate totals. It rejects competing matching player rows. Larger delivery cells keep the existing whole-image context retry. Native context crops preserve original-image coordinates, use the same 4096 decode limit and aspect bounds, require exactly one region, and omit delivery-label/stroke augmentation. This replaces a retry within the four-call limit; it adds no cloud service or call budget. Explicit vertical borders attached to OCR numbers are separated using their observed symbol boxes. Letters are never converted into score digits.

Light, low-chroma ink and bright green strike ink are isolated from the monitor background. If the broad mask cannot read a complete legal frame, two progressively stricter neutral masks can remove colored background decoration. A stricter mask never discards an already complete physical reading, and no mask is chosen by its score. Four-connected components separate characters; an enclosing split ring is removed only when it contains a separate ink component. Miss marks require a compact horizontal component in the middle of the delivery band. Short, rounded misses can have an aspect ratio as low as 1.2 only when at least 70% of their rectangle contains observed ink; ordinary thin misses retain the earlier shape checks. Digits, X, and / are compared with 24×32 binary templates rendered from OFL Roboto at six weights. Unknown shapes remain empty. Foul glyphs and unfamiliar fonts continue through native OCR/manual review.

Strong monitor/camera color casts have an additional bounded reading. One shared 95th-percentile RGB reference from the ten delivery crops normalizes the light ink when its channels differ by at least 45 and all exceed 140. Three progressively broader normalized masks remove edge-connected illustration. In this reading only, an enclosing component is a split ring when it contains a sizeable, independently template-readable digit; small illustration islands inside an outlined 8/9 or 2 cannot remove the actual glyph. Legal primary native marks must remain present, and secondary OCR can corroborate only the pixel winner. The neutral-ink row remains a separate candidate; complete conflicting rows disable automatic selection. Each candidate is read before score validation, without searching for deliveries that fit a total.

Uncorroborated template acceptance requires intersection-over-union of at least .68 and a .06 lead over other characters. An independently observed native OCR character anchored inside a component is retained, including when color thresholding fragments the photographed ink. A secondary native observation can corroborate only the same pixel winner at the same position (IoU at least .6); it cannot override a different pixel winner or any conflicting primary character. A Cyrillic З/Х lookalike is accepted only with agreement from the pixel winner, never as a global name or score substitution. Conflicting primary native observations make that frame uncertain; templates fill omissions rather than overwrite known marks. No search chooses marks to fit a total. A full legal ten-pin sequence must match the independently observed final total, plus every cumulative checkpoint available from the native grid. Multiple matching rows still require selection. The photo and all ten filled inputs remain available for visual review before saving.

Full-image/context readings are retained as alternatives to the refined reading. They share one bounded fallback raster decode; optional pixel-calibrated native crops use a separate sequential decode disposed before fallback. At most sixteen name/header layouts, two ruling polarities per layout, two ink families and four text readings are evaluated. Each pass keeps its own delivery observations and validation. A named pass without its own header fit also needs three agreeing checkpoints including the tenth. A pass that omits the name needs six agreeing checkpoints including the tenth, corroborated by six in another pass that observes the name at the same position. An explicit conflicting name blocks that recovery. A total-only donor cannot act as an independent primary reading. Identical recovered rows are deduplicated; conflicting complete readings disable automatic selection. Overlapping native words with identical text and at least 65% overlap of the smaller box are collapsed, avoiding ML Kit duplicate-block conflicts. Distinct values in the same cell remain conflicts.

League scratch and handicap-adjusted totals are separate columns. Only the nearby first total column can validate a scratch game; multiple numeric columns require an identified handicap header. The common OCR c/e confusion in `hdcp` is allowed in that label, never in score digits. If one pass loses the large scratch total, another may supply that actual observation at the same name/row position with six agreeing primary cumulative checkpoints including the tenth. A sparse delivery pass with at least three checkpoints including the tenth can instead use six checkpoints from the validating pass, provided all its observations match and at least three overlap the primary pass. A neighboring bowler, handicap total, or cumulative numbers without delivery ink cannot supply missing rolls. No handicap is added to the scratch score.

`assets/recognition/glyphs.json` is a small bundled template set, not a downloadable service or remote model. All 72 original OFL Roboto variants are preserved. Six Apache-2.0 Roboto Slab variants add the wide-footed numeral 1 while retaining the same confidence thresholds. Source URLs, font SHA-256 values, copyright and modifications are recorded alongside the masks. Regenerate using `tool/generate_score_glyphs.py` with the Google Fonts Roboto and optional Roboto Slab variable fonts and Pillow. Source fonts are not bundled. Settings → Licenses includes both template licenses.
